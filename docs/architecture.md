# 应用结构

衣间是单用户、本机运行的衣橱应用。浏览器和可选 AI 助手访问同一套衣物与事件数据。

```text
手机 / 桌面网页             Codex / Claude Code 会话
      │                         │ 短时授权 + 原生工具
      └──────── /api ────────────┘
                    │
               FastAPI 服务
          ┌─────────┼───────────┐
          │         │           │
       SQLite    本地照片    可选模型接口
                            用户选择后启用
```

## 文件与职责

- `server/store.py`：SQLite 事务和工作区版本。使用写事务维护衣物、搭配、计划及事件之间的一致性。
- `server/main.py`：衣物录入、搭配保存、日历、打包、穿着和洗护接口，以及网页资源。
- `server/recommendations.py`：真实衣物约束与规则排序。完整搭配需要上衣、下装和鞋，或连衣裙与鞋；锁定、排除、衣橱范围和不搭组合会参与校验。
- `server/catalog.py`：从穿着事件计算次数和成本；各币种独立统计。
- `server/images.py`：图片解码、规范化、原图保留、去背景及安全路径。
- `server/ai.py` 与 `server/ai_network.py`：模型连接、密钥保护、识别任务、AI 推荐、聊天和宿主配对。
- `server/backup.py` 与 `server/migration.py`：完整备份验证及旧版衣物备份导入。
- `web/`：响应式 React 界面，所有数据动作使用上述接口。
- `integrations/yijian/`：Codex / Claude Code 插件清单、Skill 和独立 Python 工具。

## 使用边界

服务监听回环地址，以本机浏览器会话和有时限的助手凭证访问数据。浏览器写操作校验来源，助手凭证只存摘要。模型配置和新授权由浏览器管理。

助手配对由 CLI 发起、浏览器确认，私密设备凭证在服务端只存摘要。客户端保存并重读授权、实际访问衣柜后才确认连接。每次配对携带独立请求编号，界面按该编号区分新配对与已有授权。凭据写入和断开操作使用系统文件锁；更新同一缓存的连接后撤销其旧授权。

同一个工作区属于一个人，不包含家庭共享、多租户、第三方登录或公网服务端。需要跨设备部署时，应在独立版本中加入用户体系和完整部署验证。

模型与图片处理在数据库事务之外执行；处理结果提交前重新检查任务状态，避免覆盖用户已确认的内容。衣物状态、识别状态与用户确认分别记录。

## 记录规则

保存搭配是保存衣物集合；日历是日期计划；打包是物品清单。三者都不代表真实穿着。实际穿着事件使用请求标识保证重复提交不会多记，撤销后统计重新计算。

删除衣物会清理搭配、计划、清单中的引用；历史穿着保留当时的衣物名称。恢复文件不会写入模型密钥和助手会话。
