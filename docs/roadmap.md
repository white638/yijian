# 项目路线

## 第一阶段：个人衣柜

完成可在本机使用的完整流程：选择或跳过 AI 连接、照片与商品链接录入、去背景、自动识别与人工确认、搭配、穿着记录、成本统计和数据备份。支持 Codex 技能、模型 API 与已有本地视觉模型服务。

发布条件是核心流程可实际操作、数据可恢复、图片与模型处理失败可见、支持平台和真实验证范围明确。

## 第二阶段：云端与自托管

状态：开发规划。当前发布版仍为本机个人应用。

第二阶段同时提供可注册使用的官方云端版和可部署在用户服务器上的自托管版。官网提供产品介绍、演示和使用入口。两版支持私密衣柜、通过链接邀请朋友提供穿搭建议，以及个人衣柜数据的双向迁移。保留本机图片处理和助手连接能力。

两版的前端、后端、数据结构、数据库迁移、数据交换协议和部署脚本均按 MIT 许可证开源，共用核心功能。生产密钥、用户数据、照片、备份和运行日志由运营者保密保存。第三方软件及模型适用各自许可证。

软件可以免费使用、修改和自行部署。官方托管的存储、备份、维护及可选 AI 服务可以独立制定服务方案；开源许可与托管服务价格分别管理。

### 部署分工

| 服务 | 职责 |
| --- | --- |
| Vercel | 官网、使用教程、演示和 React 网页界面。 |
| Cloudflare Workers | 在线 API、账号会话、访问授权和分享操作。 |
| Cloudflare D1 | 用户、衣物、搭配、分享、建议和任务等关系表。 |
| Cloudflare R2 | 私密衣物照片与受分享权限控制的照片快照。 |
| Cloudflare Queues | 有限重试的异步任务及可选远端 AI 调用。 |

官网域名指向 Vercel，API 子域交由 Worker；Cloudflare 管理 DNS 时，Vercel 对应记录使用 DNS only。

自托管版提供 Node Docker 部署包，在自己的服务器上同时提供网页和 API，使用 SQLite 与本地照片目录，也可配置 S3 兼容图片存储。官方云端使用 Vercel 与 Cloudflare，自托管安装不要求这些平台的账号。

目标架构使用 Hono 和共用的 TypeScript 业务层，账号授权、衣柜、搭配、分享与数据迁移逻辑共享，只为 Workers／Node、数据库、图片和任务存取提供适配器。现有 FastAPI 本机数据通过兼容导入器迁移，完成行为一致性及恢复验证后切换主业务实现；rembg 保留为可选本机图片处理组件。

### 账号与在线衣柜

- 建立账号、登录会话和账号恢复，衣柜默认私密。
- 使用 D1 保存结构化关系表，照片放私有 R2 存储。
- 每条私密记录关联所属用户。Worker 从已验证的会话取得身份，统一校验衣物、图片、关联记录、任务、备份及导出的归属。D1 采用应用层授权，需要用跨账号访问测试防止漏检。
- 私密图片在鉴权后访问；分享照片使用独立快照及独立访问检查。
- 提供个人数据导出、删除和可验证的数据库／图片联合备份。

当前本机服务的 SQLite 工作区属于单个用户，浏览器与助手会话共享这份数据。公网版需要数据模型和权限体系的改造，部署前必须验证不同账号之间不能读取或修改彼此的内容。

D1 使用数据库约束、条件更新及原子批处理维护关系一致性。数据库、照片和队列之间通过明确状态与补偿任务协调；删除数据库行时必须同时处理对应图片。

自托管 SQLite 与 D1 使用共同的 SQL 子集、版本化数据库迁移和同一组授权测试。应用事务限定为两端均支持的原子 SQL 批次及条件更新；自托管任务队列也需要持久化、重试限制和重复执行保护。

### 数据迁移与互通

完整搬迁是两版发布的核心验收项，覆盖云端迁至自托管，以及自托管迁至云端。迁移包括衣物照片与属性、收藏、搭配、计划、穿着与洗护记录、旅行清单、购买信息、参考价格和个人偏好。

- 两版共用稳定 UUID、数据格式版本、来源实例编号及图片 SHA-256 清单。
- 导入前展示内容数量、重复项和冲突；支持重复导入去重，保留用户已确认的修改。
- 数据归属映射到目标环境的当前账号；密码、会话、访问令牌和 AI 密钥由目标环境独立配置。
- 迁移保留原始记录关系及购买金额，参考价格维持独立字段。
- 分享历史及收到的建议可随主人数据导出，作为只读历史迁入。迁移包排除有效分享凭证和防滥用来源标识。新实例重新分享时生成新链接；原站链接的关闭与撤销仍在原站管理。

完整迁移验证后，再提供由用户主动开启的增量同步。同步使用记录版本、变更游标和删除标记；同一衣物在两端均被修改时显示冲突，由用户决定保留内容，避免静默覆盖。关闭同步后，两端继续各自使用。

当前本机版本提供完整备份和向空衣柜恢复；跨部署合并、账号映射和增量同步属于第二阶段交付。

### 分享衣柜与朋友建议

用户选择衣物、写下问题，预览朋友将看到的内容，生成有有效期的分享链接。朋友在浏览器中查看选中衣物，填写建议或选择一组搭配，无需安装应用或注册账号。主人可以查看和删除回复，将喜欢的建议保存为自己的搭配。

分享通过持有链接访问，不进入公开目录、站内搜索及 sitemap，页面设置禁止搜索引擎收录。照片快照仅保留用户确认分享的内容，清除图片元数据。购买价格、私人备注、账号信息及其他衣物字段保持私密。

主人可以关闭回复、撤销链接或重新生成链接。访问检查同时覆盖页面、照片和回复接口。提交按分享和来源限流，限制文本长度，重复提交去重；异常流量再触发验证。

移动端采用分享卡片、衣物网格和底部回复入口；桌面使用问题与衣物并排、建议表单随页可见的布局。完整流程、状态和验收要求见 [衣柜分享](sharing.md)。

### AI 与本机连接

云端 AI 配置按用户隔离并加密保存。自带密钥与平台提供额度分别展示；提供单用户预算、任务并发限制和平台费用上限。

Queues 可能重复投递。模型任务需有唯一编号和状态校验，避免重复调用收费模型；回写失败不能无条件重新发起推理。

Codex 与本地模型继续在用户电脑上运行。在线版通过可选的本机连接程序配对、提交用户授权的任务并取回结果。网站本身不能直接取得用户电脑的登录状态或模型额度。

现有 Python 去背景管线和 Codex CLI 运行于本机。云端图片处理需接入支持这些任务的独立服务或执行环境，Workers 负责鉴权、调度和结果管理。

### 上线顺序与验收

1. 公布官网介绍、功能演示、安装与使用说明。
2. 在封闭测试中验证账号隔离、私密图片、任务队列、导出／删除及两版双向迁移。
3. 同时发布云端注册入口和自托管部署包，开放在线衣柜与链接分享，完成朋友回复、保存搭配和撤销的完整流程。
4. 完成用户授权的增量同步、修改冲突处理和本机助手连接体验。

验收需覆盖跨账号访问、异步任务归属、分享撤销后图片失效、过期链接、越权衣物编号、并发回复关闭、资源限额和备份恢复。上线前按目标用户地区核验实际访问体验、平台容量限制与模型预算。
